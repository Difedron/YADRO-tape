# YADRO Tape Sort

YADRO Tape Sort - это тестовое задание в команду Tatlin.Unified DataPath.

Проект реализует сортировку целых чисел на устройстве хранения данных типа **Tape** — лента.

Основная идея проекта — отсортировать данные с входной ленты и записать результат на выходную ленту, учитывая ограничение по оперативной памяти и особенности ленточного устройства.

---

## Описание задания

В условии задано устройство хранения данных типа **лента**.

Лента работает следующим образом:

- считывающая/записывающая головка находится над текущей ячейкой;
- чтение и запись возможны только в текущую ячейку;
- лента может двигаться влево и вправо;
- перемещение ленты считается затратной по времени операцией;
- устройство не предназначено для произвольного доступа к данным.

Есть:

- входная лента длины `N`, содержащая элементы типа `integer`;
- выходная лента такой же длины;
- ограничение оперативной памяти — не более `M` байт;
- возможность использовать разумное количество временных лент.

Необходимо записать в выходную ленту элементы с входной ленты, отсортированные по возрастанию.

---

## Основная идея решения

Так как входная лента может быть очень большой, а оперативная память ограничена, нельзя просто считать все числа в `std::vector`, отсортировать их и записать обратно.

Поэтому в проекте используется алгоритм **External Merge Sort**( то есть внешняя сортировка слиянием).

Этот алгоритм хорошо подходит для случаев, когда данные не помещаются целиком в оперативную память.

---

## Почему выбран External Merge Sort?

Обычная сортировка, например:

```cpp
std::sort(data.begin(), data.end());
```

подразумевает, что все данные уже находятся в оперативной памяти.

Но по условию память ограничена параметром `M`, поэтому такой подход не подходит для больших входных данных.

В свою очередь EMS решает эту проблему:

1. данные читаются небольшими блоками.
2. каждый блок помещается в память и сортируется.
3. отсортированные блоки записываются во временные файлы.
4. затем временные блоки соединяются в один общий отсортированный результат.

Такой подход не требует загружать всю входную ленту в память одновременно.

---

## Как работает алгоритм?

Алгоритм состоит из двух основных этапов.

### 1. Создание отсортированных временных блоков

Сначала входная лента читается блоками.

Размер блока определяется ограничением памяти:

```text
max_numbers = memory_limit_bytes / sizeof(int)
```

Например, если:

```text
memory_limit_bytes = 12
sizeof(int) = 4
```

то за один раз можно прочитать только 3 числа.

Данный параметр меняется в файле config.txt, там же меняются остальные параметры задержки ленты.

Каждый блок:

1. читается с входной ленты;
2. сохраняется во временный `std::vector<int>`;
3. сортируется с помощью `std::sort`;
4. записывается во временную ленту в директории `tmp`.

Пример:

```text
input: 8 3 1 7 4 2 9 5
```

При `memory_limit_bytes = 12` получаются блоки:

```text
8 3 1   -> 1 3 8
7 4 2   -> 2 4 7
9 5     -> 5 9
```

В директории `tmp` создаются временные файлы:

```text
tmp/run_0.txt
tmp/run_1.txt
tmp/run_2.txt
```

---

### 2. Слияние временных блоков

После создания временных отсортированных лент они сливаются в один общий отсортированный поток.

Для этого используется `std::priority_queue`.

В кучу помещается первый элемент каждой временной ленты. Далее алгоритм каждый раз:

1. берёт минимальный элемент из кучи;
2. записывает его в выходную ленту;
3. считывает следующий элемент из той же временной ленты;
4. добавляет его в кучу;
5. повторяет процесс, пока все временные ленты не закончатся.

Итоговый результат:

```text
1 2 3 4 5 7 8 9
```

## Описание основных компонентов

### `ITape`

Файл:

```text
include/ITape.h
```

Это интерфейс для работы с устройством типа лента.

Он описывает базовые операции, которые должна поддерживать любая реализация ленты:

```cpp
virtual int read() = 0;
virtual void write(int value) = 0;

virtual void moveLeft() = 0;
virtual void moveRight() = 0;
virtual void rewind() = 0;

virtual bool isEnd() const = 0;
```

Этот интерфейс нужен, чтобы отделить саму идею ленты от конкретного способа её реализации.

---

### `FileTape`

Файлы:

```text
include/FileTape.h
src/FileTape.cpp
```

`FileTape` — это класс, который реализует интерфейс `ITape` и эмулирует работу ленты через обычный файл.

Внутри класса хранится:

- имя файла;
- текущая позиция головки;
- размер ленты;
- настройки задержек;
- файловый поток.

Каждая ячейка ленты хранится в файле с фиксированной шириной. В реализации используется ширина 12 символов на одно число.

Это нужно для того, чтобы можно было корректно перейти к нужной ячейке файла:

```text
позиция 0 -> байт 0
позиция 1 -> байт 12
позиция 2 -> байт 24
```

Так файл становится похож на набор ячеек ленты.

---

### `TapeConfig`

Файлы:

```text
include/TapeConfig.h
src/TapeConfig.cpp
```

`TapeConfig` отвечает за чтение конфигурации из файла `config.txt`.

Через конфиг задаются:

- задержка чтения;
- задержка записи;
- задержка сдвига;
- задержка перемотки;
- ограничение оперативной памяти.

Это позволяет менять параметры работы программы без перекомпиляции.

---

### `TapeSorter`

Файлы:

```text
include/TapeSorter.h
src/TapeSorter.cpp
```

`TapeSorter` реализует алгоритм сортировки.

Основные методы:

- `createSortedRuns(...)` — создаёт временные отсортированные блоки;
- `mergeRuns(...)` — сливает временные блоки в выходную ленту;
- `sort(...)` — общий метод, который выполняет сортировку целиком.

---

### `main.cpp`

Файл:

```text
src/main.cpp
```

Основная программа:

1. принимает имена входного и выходного файлов из аргументов командной строки;
2. читает настройки из `config.txt`;
3. определяет количество чисел во входном файле;
4. подготавливает входную ленту во временном файле;
5. запускает сортировку;
6. записывает результат в выходной файл.

## Конфигурационный файл

Файл:

```text
config.txt
```

Пример содержимого:

```text
read_delay_ms=0
write_delay_ms=0
move_delay_ms=0
rewind_delay_ms=0
memory_limit_bytes=12
```

Описание параметров:

| Параметр | Значение |
|---|---|
| `read_delay_ms` | задержка чтения одного элемента с ленты |
| `write_delay_ms` | задержка записи одного элемента на ленту |
| `move_delay_ms` | задержка сдвига ленты на одну позицию |
| `rewind_delay_ms` | задержка перемотки ленты в начало |
| `memory_limit_bytes` | ограничение оперативной памяти в байтах |

Все параметры можно менять без перекомпиляции проекта.

Например, если нужно увеличить доступную память:

```text
memory_limit_bytes=4096
```

Если нужно включить задержки:

```text
read_delay_ms=10
write_delay_ms=10
move_delay_ms=5
rewind_delay_ms=50
memory_limit_bytes=1024
```

---

## Формат входного файла

Входной файл должен содержать целые числа, разделённые пробелами или переносами строк.

Пример:

```text
15 -3 8 8 0 42 -10 7 1 15
```

Также допустим вариант:

```text
15
-3
8
8
0
42
-10
7
1
15
```

---

## Формат выходного файла

Выходной файл содержит отсортированные числа.

Для входа:

```text
15 -3 8 8 0 42 -10 7 1 15
```

результат будет:

```text
-10 -3 0 1 7 8 8 15 15 42
```

Важно: в выходном файле между числами могут быть большие пробелы. Это связано с тем, что файл используется как эмуляция ленты с фиксированным размером ячейки.

Например файл может выглядеть так:

```text
         -10          -3           0           1           7           8           8          15          15          42
```

Это нормально. Такой файл корректно читается через `std::ifstream`.

## Временные файлы

Во время работы программа создаёт временные файлы в директории `tmp`.

Пример:

```text
tmp/input_tape.txt
tmp/run_0.txt
tmp/run_1.txt
tmp/run_2.txt
```

Назначение файлов:

| Файл | Назначение |
|---|---|
| `input_tape.txt` | подготовленная входная лента в формате фиксированных ячеек |
| `run_*.txt` | временные отсортированные блоки |

Эти файлы создаются во время выполнения программы и не добавляются в репозиторий благодаря `.gitignore`.

В репозитории папка `tmp` хранится с помощью файла:

```text
tmp/.gitkeep
```

## Подключение Catch2

Catch2 подключается через CMake с помощью `FetchContent`.

Это значит, что при первой сборке CMake автоматически загрузит Catch2 из GitHub.

Фрагмент из `CMakeLists.txt`:

```cmake
include(FetchContent)

FetchContent_Declare(
        Catch2
        GIT_REPOSITORY https://github.com/catchorg/Catch2.git
        GIT_TAG v3.8.1
)

FetchContent_MakeAvailable(Catch2)
```

Если при первой сборке возникнет ошибка загрузки Catch2, нужно проверить интернет-соединение или доступ к GitHub.

## Особенности и нюансы реализации

- Входной файл пользователя сначала преобразуется во временную файловую ленту `tmp/input_tape.txt`.
- Это нужно, потому что `FileTape` работает с фиксированным размером ячейки.
- Временные отсортированные блоки сохраняются в `tmp/run_*.txt`.
- Итоговый `output.txt` также имеет формат ленты с фиксированной шириной ячеек.
- Большие пробелы в выходном файле не являются ошибкой.
- Ограничение памяти применяется при создании отсортированных блоков.
- Программа не загружает всю входную ленту в память целиком.
- Основной алгоритм сортировки вынесен в отдельный класс `TapeSorter`.
- Работа с лентой вынесена в интерфейс `ITape` и реализацию `FileTape`.
